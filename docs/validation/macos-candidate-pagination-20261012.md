# macOS 单行候选分页修复

## 问题确认

在 v1.1.1 与当前主线的候选实现中，`candidatePages` 已按宽度分割一个 Rime 页，但 `renderCompactRow` 只渲染当前子页，没有翻页入口。Page Up/Down 及默认的 `-`/`=` 仍直接交给 Rime，可能跨过未显示的后半页；紧凑模式的数字键也直接使用引擎页索引。左右键移动本地高亮才会揭示这些候选。

因此“引擎有 9 个、屏幕只见 7 个”的反馈有明确的代码路径支持；未取得原反馈者的拼音、字体和屏幕参数，未声称复现其原始宿主环境。

## 变更

- 外观 → 尺寸加入每页候选数，范围 1–9，默认 9，作为单行显示上限。数量设置不重部署或覆盖用户 Rime 方案。
- 先预留翻页按钮宽度，再依据最大宽度、字体、注释与数量分成连续可见页；末页缩短不改变分页边界。
- 紧凑模式的翻页按钮、Page Up/Down 和 `-`/`=` 先遍历宽度或数量产生的分页，再切换引擎页。反向跨引擎页时落到上一页的最后一段。
- 数字编号每个可见页从 1 重新开始，映射回实际引擎索引；未显示的编号不会选中隐藏词。Rime 的选择键与装饰性标签分开传递，自定义非数字选择键保留原有路由。
- 设置预览复用分页逻辑并支持点击翻页；沿用单进程 IMK、精确焦点所有权与原选词提交路径。

交互参考：[Squirrel 官方配置的翻页箭头说明](https://github.com/rime/squirrel/blob/master/data/squirrel.yaml)。本修复在存在前后页时直接显示翻页按钮，避免让用户猜测还有候选。

## 验证

- Debug 与 Release 编译通过。
- `candidate-pagination-smoke`：1,072 项检查，198 个实际 AppKit 页面通过；覆盖 360/622/900 宽度、1/5/9 数量、12/24 字号、长候选、注释、装饰性序号、前后页边界、数字索引和按钮布局。
- 隔离的 librime `rime_ice` 输入 `shi` 产生 9 个候选；5+4 分页、后续引擎页、返回上一页及溢出候选提交均通过。7+2 的精确宽度分割也有回归断言。
- `candidate-metrics-smoke`、`matrix-smoke`、`candidate-commit-smoke`、`buffer-window-smoke`、`smoke` 均通过。
- 新增分页检查已加入 macOS CI 命令列表；本次为本地验证，尚未运行远端 CI。
- 原生渲染图保存在忽略目录 `.build/validation/candidate-pagination-20261012/`，不创建额外注册的 IME app。

系统级输入法的安装与宿主实测需要单独核验，以上通过项不代表已替换 `/Library/Input Methods/RIMES.app`。
