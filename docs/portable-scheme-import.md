# 跨平台输入方案导入

本次实现范围：macOS、iOS、Android、Windows、Linux 的灵犀输入法；Rime 输入方案和通用 UTF-8 文本词库。专有词库转换、第三方键盘皮肤不在本次范围内。源代码入口已实现；每端的自动测试与真机边界见文末，构建成功不等于公开安装包已经更新。

## 调研结论

- [Rime 方案规范](https://github.com/rime/home/wiki/RimeWithSchemata)：以 `.schema.yaml` 描述输入规则，以 `.dict.yaml` / `import_tables` 组织词典，`.custom.yaml` 覆盖配置，部署时生成平台本地缓存。
- [Rime 定制指南](https://github.com/rime/home/wiki/CustomizationGuide)和 [plum](https://github.com/rime/plum)：安装资源、登记启用方案、部署是三个不同步骤；一个方案可能依赖其他方案、Lua 和 OpenCC 资源。
- [仓输入方案示例](https://github.com/imfuxiao/HamsterInputSchemas)和 [同文指南](https://github.com/osfans/trime/wiki/UserGuide)：移动端也使用 Rime 源文件；键盘布局/主题是宿主功能，不能把其他输入法的 UI 配置当作可移植的输入方案。
- [雾凇拼音](https://github.com/iDvel/rime-ice)和[万象](https://github.com/amzxyz/rime-wanxiang)：真实包包含词典子目录、Lua 子模块、反查、转换数据及可选组件。应适配导入器，而不是要求用户为每个平台重新打包。

## 同一份文件

交付物使用普通 ZIP，保留标准 Rime 源文件及相对目录。五端对同一个 SHA-256 的 ZIP 进行检查、部署、启用。单层或多层外包装目录可以自动识别；忽略 `__MACOSX`、AppleDouble、`build`、`sync` 和用户数据库，不导入其他设备的私有状态。存在互不包含的多个方案根目录时，应给出明确诊断，不能随意拼接不同方案。

兼容已有的可选 `rimes-package.yaml`（`rimes_package.format: 1`）；上游原包没有清单也能导入。原生 Rime 文件是事实来源，清单只能提供标题、推荐方案、来源、许可证和明确的能力要求，不能授权执行安装脚本或覆盖宿主设置。

## 导入生命周期

1. 只读检查原 ZIP，预览方案名称、依赖、资源大小和兼容说明。
2. 在独立暂存目录按原目录解压，验证路径、大小、CRC 和依赖；必要的格式修正只写入副本并列出说明。
3. 以本机 Rime 引擎编译并加载检查。静态检查不能替代引擎对配置、Lua 和词典的最终验证。
4. 成功后原子发布到方案库；启用是明确的独立操作。失败不修改当前输入方案、学习词库和用户设置。
5. 删除导入包时清理其源文件和编译缓存，保留用户学习数据。内置方案始终可作为回退。

配置引用遵循 Rime 的本地路径、`.yaml` 后缀和 `?` 可选依赖语义。不能把 YAML 节点路径的 `/` 当作文件系统绝对路径。检查实际生效的 schema 补丁；Lua 依赖检查必须区分代码、字符串、长字符串和注释，支持 `*module*member` 及 `module/init.lua`。

## 能力与边界

验收覆盖全拼、主流双拼、五笔、仓颉/速成、郑码、音形码、注音、粤拼等代表方案。类别名称不代表所有第三方发行版都受支持：包必须包含必需源文件；模型、原生扩展、宿主专用 Lua 接口要单独检查。缺少必需能力时明确报错，不能删掉功能后宣称原方案完整可用。

通用词库先支持带编码的 UTF-8 文本/TSV（词条、编码、可选权重）。标准 `.dict.yaml` 随对应 `.schema.yaml` 放在 ZIP 内导入；文件选择器不把孤立的 `.dict.yaml` 当成完整方案。纯汉字词表没有唯一可靠的读音/形码，必须提供编码或选定适用的转换方式，不能静默猜码。键盘布局导入与方案导入保持独立。

## 验收证据

同一套原包和故障样本用于各端回归：外包装目录、元数据、词典子目录、配置补丁、可选引用、Lua 注释/子模块、大词典，以及越界路径、重复文件、缺失依赖、损坏 ZIP。分别记录检查、部署、启用、真实输入、重启恢复和删除；构建通过不等于真机验收完成。

## 设置入口与生效

| 平台 | 入口 | 导入后生效方式 |
|---|---|---|
| iOS | App 设置 → Rime 方案包与导入 | 选择、部署、启用；重新唤起键盘 |
| Android | App 设置 → Rime 方案包与导入 | 独立导入进程编译，启用后重新唤起键盘 |
| macOS | 设置 → 输入法 → 导入与管理方案 | 编译后启用，重启输入法；学习数据保留 |
| Windows | 设置 → 输入法 → 导入与管理方案 | 编译后启用，保存 Buffer 后从托盘退出并重新启动 |
| Linux | Fcitx5 输入法配置，或应用列表“灵犀输入法 · 方案管理” | 编译后启用，重启 Fcitx5 |

Linux 入口属于 RIMES Fcitx5 插件，旧的数据预览安装器仍然只是给其他 Rime 前端安装数据。
Windows/macOS/Linux 的内置方案配置保留；恢复内置后继续使用先前设置。编译、启用是两个独立操作。

## 文件与运行能力

- ZIP ≤256 MiB，单资源 ≤128 MiB，展开 ≤512 MiB，≤4096 个条目，≤32 个方案，压缩比 ≤100 倍。
- 配置文件 ≤512 KiB，Lua 源文件 ≤1 MiB，部署后总量 ≤512 MiB。
- 不接受 Windows 设备保留名、路径越界、符号链接、大小写或 Unicode 规范化后的重名。
- TXT/TSV 一行是 `词条<TAB>编码<TAB>可选权重`；编码为小写 ASCII 字母、数字或常用编码符号，权重为非负 32 位整数。支持 UTF-8 BOM、LF、CRLF、CR 换行和 `#` 注释，生成独立码表方案。
- 五端的统一基础范围不含 `.gram` 语言模型。包含模型的 ZIP 会明确拒绝，避免丢掉模型后仍宣称完整兼容。未带模型的万象基础包验收只证明基础输入，不能证明“小模型”能力。
- 移动端 Lua 仅能访问引擎资源/私有数据目录，有执行预算，不运行系统命令或加载原生模块。桌面前端专有 API、皮肤、触屏布局、按键释放并击行为需要对应宿主支持。
- Linux 的发行版运行库可能过旧。`scripts/build-engine.py` 可在私有前缀构建与移动端一致的 Rime/Lua 版本；具体步骤见 [Linux README](../platforms/linux/ime/README.md)。导入检查会触发输入处理链，并拒绝已观察到的 Lua/组件加载错误，保留原方案。
