# 学习词库异常提示与恢复

当 `.userdb/LOG` 报告 `Compaction error`、`Corruption` 或读写错误时，
基础词典仍可能提供候选，但学习词已经不能正常使用。XSIME 会在主日志中
写入 WARNING，并在状态菜单、设置的输入方案及词库页面显示提示。
检查在后台进行，不读取或记录学习词正文，也不自动删除、隔离或重建词库。

## 先保留原始数据

退出 XSIME，备份整个 `~/Library/RIMES`，包括出问题的 `.userdb` 目录。
不要只备份 `LOG`，也不要把删除数据库当作恢复方法。若需要报告问题，
可提供报错类别、XSIME 版本、外部工具及其依赖版本；数据库和学习快照
含有个人输入记录，不要直接上传到公开 issue。

## 外部工具的压缩格式兼容

[#130](https://github.com/scholay/xsime/issues/130) 的报告环境中，外部工具使用了
启用 Snappy 的 LevelDB，而输入法运行库不能读取该压缩格式，出现
`corrupted compressed block contents`。此报错也可能来自实际损坏，不能仅
凭日志就断定是压缩选项不一致。

应先使用能正常读取原库的工具，从**备份副本**导出 Rime 文本学习快照
（`.userdb.txt`）。确认导出成功并核对条目后，再用与输入法运行库兼容的
工具恢复到新库，或通过 XSIME 的学习词库导入入口导入该文本快照。
无法完整导出时，保留原库继续排查；空候选或空导出不表示原数据为空。

该报告使用关闭 Snappy 的 LevelDB 重新编译外部 librime 工具后，成功恢复
了快照。维护原始二进制 userdb 时，应核对工具与目标输入法的 LevelDB
压缩能力；跨工具迁移优先使用文本快照，不直接复制压缩配置不明的数据库。

恢复后重新启动输入法，确认已知学习词能进入候选，并检查当前 `LOG`
没有新增错误。旧 `LOG.old` 不用于当前告警，避免把历史故障当作仍在发生。
