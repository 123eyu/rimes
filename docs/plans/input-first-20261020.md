# 下一版开发准备：以中文输入为中心

2026-10-20（日本时间）。维护者本轮方向：**以输入法本位为原则，梳理中文输入社区的输入习惯和客制化配置，再进入开发。**

状态：调研与开发拆分。本文提出本轮范围、行为规范和验收办法，不表示功能已经实现。版本号、最终交付项和发行时间在范围冻结后确定。源码基线为 `588e1462`，公开发行基线为 [v1.1.7](https://github.com/scholay/xsime/releases/tag/v1.1.7)。

## 1. 本轮产品目标

用户不用打开 Buffer、登录账号或配置 AI，就能稳定地输入中文、选择候选、切换方案和调整习惯。高级用户能保留自己的 Rime 文件与定制，普通用户能用设置页面完成常见调整。

本轮优先级：**普通输入可靠性 → 方案与配置可靠性 → 候选和移动键盘体验。**

2026-10-20 范围确认：维护者已授权五端同步实施；**词库与短语新增功能暂缓**。现有数据保护与词库故障不导致输入失效的回归仍保留。下文词库/短语设计仅留作后续参考，不进入本轮开发或发版承诺。

“所有 issue 都处理一下”落实为逐项分流和更新证据，并不要求发版前完成全部长期需求。当前 88 个开放 issue 中，10 个带 `bug`、72 个带 `enhancement`，标签存在重叠；27 项属于旧 Linux 对齐里程碑。逐项建议见[全量 issue 分流表](input-first-issues-20261020.md)。

- Buffer、AI、Mailbox、Capsule、云服务的新工作流留在原路线图，现有功能继续做受影响回归。如果它们导致普通输入卡顿、丢字或抢焦点，相关缺陷立即进入本轮基础修复。
- 语音、手写也是输入能力，保留为后续输入专项；先定义识别结果确认与平台权限，不为本版引入完整识别引擎或服务。
- 五端统一行为定义和可移植配置；桌面快捷键、移动触控和系统权限分别实现，不要求五端界面一模一样。

## 5. 配置如何实现

### 5.1 五端同义、分层保存

设置按五组组织：**输入习惯、当前方案、候选与显示、键盘与按键、词库与短语**。每个控件解释具体后果，复杂项附一个可验证例子。高级编辑折叠，不要求普通用户先读 YAML。

配置分三层：

1. **方案层**：原生 Rime 资源和现有 `.custom.yaml` 保持事实来源。宿主生成自己的可追踪覆盖，不直接改上游原件或任意覆盖用户手写补丁。
2. **产品偏好层**：给用户选项稳定的语义标识、类型、范围、默认来源、方案身份、所需能力、生效方式和配置修订号。Swift、Java、C++ 消费相同规范和样本，不要求共用同一实现语言。
3. **设备层**：字体、像素尺寸、应用身份、系统快捷键与权限保留本机适配。导出可携带可选设备配置，但接收端先检查兼容性，不直接照搬。

没有单一“全局强制覆盖所有方案”的优先级。方案作者默认、用户原有补丁和设置页面的冲突须明确展示；恢复默认只撤销本产品管理的覆盖，不能删除用户文件。未知 YAML 键与自定义组件原样保留。

### 5.2 能力识别

- 根据实际部署配置、组件和引擎探测识别能力；内置方案可提供已验证的显式映射。不能只判断文件名含 pinyin/wubi。
- 将状态区分为可配置、由外部文件管理、缺少能力和探测失败。未知方案仍能输入、切换和查看诊断，不自动生成不可靠表单。
- 模糊音、四码上屏、反查、学习、繁简及字集分别声明依赖；没有对应数据/组件就不显示误导性开关。
- 控件值要来自有效配置；“已保存”与“已应用”分开，状态可读回。

### 5.3 生效、迁移和回滚

设置预览 → 校验 → 写入版本化草稿 → 必要时后台部署 → 引擎加载/实际候选检查 → 发布新配置修订。

- 已部署方案切换应在当前组字安全结束后应用；必要部署完成后自动切入，不依赖用户手工切到其他输入法再回来。不得偷偷提交或丢弃未完成组字。
- 外观/反馈等无需重新编译的项即时生效；布局变化在触控结束后应用，不能在手势中途改变按键含义。
- 同一方案更新、重启、升级和失败回滚都保留用户覆盖；设置并发修改要检测修订变化，不让旧 App 快照覆盖键盘中的新值。
- 导出可移植偏好、Rime 补丁和用户选择的短语；不默认携带账号凭据、其他输入法数据或全部输入历史。先复用现有方案 ZIP，新增元数据规范单独版本化，不与既有包清单职责混淆。

### 5.4 词库与方案分开

界面区分三个动作：导入输入方案、给兼容的当前方案追加词库、管理个人短语。后两项需要实现新的适配与验证，不复用“生成独立方案”后宣称完成。

- 首批继续支持 Rime 文件和带编码 UTF-8 TXT/TSV；专有词库转换不进入本版。没有编码的纯汉字列表必须给出明确说明，不能静默猜读音或形码。
- 词库追加前预览目标方案、有效/无效行、重复条目和冲突；增量资源与学习库分离，成功后再激活，失败保留旧输入能力。
- 用户词库故障提示提供可操作的导出/备份/恢复路径；不因检测失败自动删库。

### 5.5 首批字段契约草案

以下是产品语义字段，不是要求直接把这些名字写进 Rime 配置。`inherit` 表示读回现行有效值，不是某个隐含的新默认。引擎映射必须按能力适配验证；没有映射的字段标为不可用。移动设备参数单独保存，不能覆盖导入方案的编码规则。

| 语义字段 | 值与作用域 | 生效方式 / 实现约束 |
|---|---|---|
| `input.initialMode` | inherit / 中文 / 英文；每方案 | 通过真实开关身份映射，不能假定 `switches/@0` 永远是中英开关；不改变当前未提交组字 |
| `input.switchKey` | inherit / 不绑定 / 平台支持的键；每设备 | 桌面单击修饰键与组合键区分；先检测系统和已有快捷键冲突 |
| `input.switchAction` | inherit / 提交候选 / 提交原码 / 临时英文；每方案 | 仅暴露当前引擎支持的切换动作；空组字、组字中和候选中分别测试 |
| `punctuation.mode` | inherit / 中文 / 英文；每方案 | 与输入语言独立，映射到实际标点组件/开关 |
| `punctuation.width` | inherit / 半角 / 全角；每方案 | 不替换系统快捷键含义；方案有能力才允许设置 |
| `characters.outputVariant` | inherit / 简体 / 繁体 / 可用地区形式；每方案 | 核对实际 OpenCC 数据与过滤器；必要时重新部署 |

## 8. 验收与发版门槛

### 普通输入先验收

所有平台先在 Buffer 关闭时验证内置全拼、双拼、五笔及至少一份标准导入包。覆盖字母/中文/数字/标点混输、候选分页、连续删除、换框、切应用、选区替换、撤销、锁屏唤醒和系统搜索。保护字段遵循系统契约，绝不为“能打字”恢复学习、日志正文或强制注入。

### 行为样本固定

至少覆盖：

- `nihao` 正常组字；全拼/双拼分别验证模糊音开关，不改变其他方案。
- 中文和英文模式分别输入 `? ! : ^`、网址、邮箱、小数；Shift/Ctrl/Alt/Command 组合键不被误吞。
- 四码唯一、四码多候选、四码无候选、第五码合法形码、第五码为标点，以及 `z` 反查；两个上屏开关形成四种组合，验证不漏掉第五键、不误提交反查。
- 候选缩放、长词、注释、多屏/小屏；显示序号和真正提交的候选一致。
- 点击、直接上滑、长按上滑、取消、手指滑出、双指快打、连续删除；每次手势恰好一次输出。
- 同一配置跨五端导入、重启、覆盖更新、外部补丁冲突、无效值、缺资源与部署失败；旧输入仍可用，原用户数据保持。
- 短语重复、编码冲突、学习词遗忘、词库损坏；失败提示可操作，恢复不依赖删掉全部用户数据。

### 性能与实际宿主

针对 #184，以 App 前台/后台/已结束、普通/并击、内置/导入方案分组，进行至少 30 分钟持续输入与切换。记录初始化耗时、按键到候选/提交的 p50/p95/p99、主线程停顿和内存趋势；统一设备、构建配置、输入样本与冷热状态。先测量基线再冻结数值门槛，不能凭空宣称解决卡顿。震动手感另由实际设备确认。

按维护者现有要求，产品构建与自动测试走远端 CI，本机不运行产品测试。Windows 的真实开始菜单、Linux X11/Wayland、iOS/Android 触控和长时间使用仍需明确的实际宿主证据；复用维护者已经明确确认且匹配本次构建/行为的验收，不重复把已验收项变成待确认。

阻断发布的是仍可复现的普通输入失败、丢字/重复上屏、焦点串投、用户词库损坏、明显性能退化，以及本版承诺设置无法生效/恢复。未确认根因的反馈先分诊；本轮未选入的长期功能不能自动阻断发布。

### Issue 与发行事实

每项记录：原问题 → 对应提交 → 自动检查 → 真实宿主/维护者确认 → 所属发行版本。验收满足后可关闭并注明已发布或计划进入下一版；只合并代码、只通过编译、只更新路线图不作为关闭依据。维护总单按子项推进，不与单个缺陷一起机械关闭。

版本发布时重新冻结 main 提交，核对官方插件锁定版本，构建并读回五端对应资产与更新清单。iOS 采用商店更新流程；上传、审核、商店可用分别记录。保持备份、stash、本地验收资料和原始用户数据。
